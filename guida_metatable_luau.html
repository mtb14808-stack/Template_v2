1Cosa sono le Metatable

Una metatable è una tabella speciale che puoi collegare a un'altra tabella per cambiarne il comportamento di default. Normalmente una tabella Lua fa solo poche cose: leggere una chiave, scriverla, calcolarne la lunghezza. Le metatable ti permettono di intercettare e ridefinire ognuna di queste operazioni tramite dei campi speciali chiamati metamethods (nomi che iniziano sempre con due underscore, es. __index).

In pratica le metatable sono il meccanismo che sta dietro a quasi tutto ciò che sembra "magico" in Luau:
  • Come funzionano le classi e l'ereditarietà (non esistono nativamente in Lua — sono simulate con metatable).
  • Come Vector3.new(1,2,3) + Vector3.new(1,1,1) riesce a sommare due vettori con +.
  • Come print(oggetto) può stampare qualcosa di leggibile invece di table: 0x123abc.
  • Come una libreria può rendere una tabella "di sola lettura" o "readonly".

Ogni tabella può avere al massimo una metatable, ma la stessa metatable può essere condivisa da tante tabelle diverse — è esattamente così che funzionano le classi.

2setmetatable() e getmetatable()

FunzioneCosa fa
setmetatable(t, mt) Collega la tabella mt come metatable di t. Restituisce t stesso (comodo per concatenare).
getmetatable(t) Restituisce la metatable di t, o nil se non ne ha una. 
local t = {}
local mt = { __index = function(table, key)
	return "chiave '" .. key .. "' non trovata!"
end }

setmetatable(t, mt)

print(t.Nome) --> "chiave 'Nome' non trovata!"
print(getmetatable(t) == mt) --> true

3__index — il più importante

__index si attiva quando leggi una chiave che non esiste nella tabella. Può essere di due tipi:

TipoComportamento
Una tabellaLua cerca la chiave mancante in quella tabella (comportamento "eredita da").
Una funzioneViene chiamata come function(t, key) e il suo valore di ritorno diventa il risultato della lettura.

__index come valore di default

local defaults = { Velocita = 16, Salute = 100 }

local player = setmetatable({ Velocita = 24 }, { __index = defaults })

print(player.Velocita) --> 24  (esiste già in player, __index non serve)
print(player.Salute)   --> 100 (non esiste in player, va a cercarla in defaults)

__index come funzione (calcolato al volo)

local rettangolo = setmetatable({ Larghezza = 4, Altezza = 3 }, {
	__index = function(self, key)
		if key == "Area" then
			return self.Larghezza * self.Altezza
		end
		return nil
	end,
})

print(rettangolo.Area) --> 12, calcolato ogni volta che lo leggi
Attenzione: __index scatta SOLO quando la chiave non è già presente nella tabella stessa. Se player.Velocita esistesse già, __index non verrebbe mai chiamato per quella chiave.

4__newindex — intercettare le scritture

Il contrario di __index: scatta quando provi a scrivere una chiave che non esiste ancora nella tabella. Se la chiave esiste già, la scrittura avviene normalmente e __newindex non viene chiamato.

local log = {}

local watched = setmetatable({}, {
	__newindex = function(t, key, value)
		table.insert(log, key .. " = " .. tostring(value))
		rawset(t, key, value) -- scrive DAVVERO nella tabella, bypassando la metatable
	end,
})

watched.Nome = "Mario"
watched.Vita = 100

print(log[1]) --> "Nome = Mario"
print(watched.Nome) --> "Mario" (è stato scritto davvero grazie a rawset)
Fondamentale: dentro __newindex devi usare rawset(t, key, value) per scrivere davvero il valore. Se scrivessi t[key] = value normalmente, richiameresti di nuovo __newindex — loop infinito.

5Costruire una classe OOP

Lua non ha classi native: si simulano combinando __index con una funzione costruttore. È il pattern OOP standard che trovi in praticamente ogni modulo Roblox (Signal, Maid, Promise, ecc.).

local Account = {}
Account.__index = Account -- la tabella è metatable di se stessa!

function Account.new(balance: number)
	local self = setmetatable({}, Account)
	self.Balance = balance
	return self
end

function Account:Deposit(amount: number)
	self.Balance += amount
end

function Account:Withdraw(amount: number)
	if amount > self.Balance then
		error("Fondi insufficienti")
	end
	self.Balance -= amount
end

local conto = Account.new(100)
conto:Deposit(50)
print(conto.Balance) --> 150

Quando scrivi conto:Deposit(50), Lua traduce in conto.Deposit(conto, 50). Ma conto non ha una chiave Deposit — quindi scatta __index, che punta ad Account, dove Deposit esiste davvero. Ecco perché ogni istanza "eredita" i metodi.

Ereditarietà tra classi

local SavingsAccount = setmetatable({}, { __index = Account }) -- eredita da Account
SavingsAccount.__index = SavingsAccount

function SavingsAccount.new(balance: number, rate: number)
	local self = Account.new(balance) -- riusa il costruttore della classe base
	self.Rate = rate
	return setmetatable(self, SavingsAccount) -- "promuove" self alla sottoclasse
end

function SavingsAccount:ApplyInterest()
	self.Balance += self.Balance * self.Rate
end

local risparmio = SavingsAccount.new(1000, 0.05)
risparmio:Deposit(200)   -- metodo ereditato da Account
risparmio:ApplyInterest() -- metodo proprio di SavingsAccount
print(risparmio.Balance) --> 1260
Catena di ricerca: quando cerchi risparmio:Deposit, Lua controlla prima risparmio (non c'è), poi SavingsAccount tramite il suo __index (non c'è nemmeno lì), poi Account tramite IL __index di SavingsAccount stesso (che punta ad Account) — e lì lo trova. Puoi incatenare quante classi vuoi così.

6Metamethods aritmetici

Permettono di usare gli operatori matematici (+ - * / % ^ -) direttamente sulle tue tabelle, esattamente come fai già con Vector3 o Color3.

MetamethodOperatoreFirma
__adda + bfunction(a, b)
__suba - bfunction(a, b)
__mula * bfunction(a, b)
__diva / bfunction(a, b)
__moda % bfunction(a, b)
__powa ^ bfunction(a, b)
__unm-a (negazione unaria)function(a)
__idiva // b (divisione intera, estensione Luau)function(a, b)
local Vector2D = {}
Vector2D.__index = Vector2D

function Vector2D.new(x: number, y: number)
	return setmetatable({ X = x, Y = y }, Vector2D)
end

Vector2D.__add = function(a, b)
	return Vector2D.new(a.X + b.X, a.Y + b.Y)
end

Vector2D.__mul = function(a, b)
	-- b può essere un altro Vector2D O un numero, gestiamo entrambi
	if typeof(b) == "number" then
		return Vector2D.new(a.X * b, a.Y * b)
	end
	return Vector2D.new(a.X * b.X, a.Y * b.Y)
end

local a = Vector2D.new(1, 2)
local b = Vector2D.new(3, 4)

local somma = a + b        -- Vector2D(4, 6)
local scalato = a * 10     -- Vector2D(10, 20)

7Metamethods di confronto

MetamethodOperatore
__eqa == b
__lta < b
__lea <= b
Nota: __eq scatta solo confrontando due tabelle (non un numero con una tabella), e solo se le due tabelle non sono già lo stesso riferimento in memoria (in quel caso Lua le considera già uguali senza nemmeno chiamare __eq). 
local Card = {}
Card.__index = Card

function Card.new(rank: number)
	return setmetatable({ Rank = rank }, Card)
end

Card.__eq = function(a, b) return a.Rank == b.Rank end
Card.__lt = function(a, b) return a.Rank < b.Rank end
Card.__le = function(a, b) return a.Rank <= b.Rank end

local re = Card.new(13)
local fante = Card.new(11)

print(re > fante) --> true (Lua riusa __lt invertendo gli argomenti)
print(re == Card.new(13)) --> true

8__tostring

Personalizza cosa succede quando la tabella viene convertita in stringa, ad esempio con print() o tostring().

local Vector2D = {}
Vector2D.__index = Vector2D

function Vector2D.new(x, y)
	return setmetatable({ X = x, Y = y }, Vector2D)
end

Vector2D.__tostring = function(self)
	return `Vector2D({self.X}, {self.Y})`
end

local v = Vector2D.new(3, 4)
print(v) --> Vector2D(3, 4)   invece di "table: 0x123abc"

9__call

Rende una tabella "chiamabile" come se fosse una funzione — utile per pattern come i costruttori compatti o le classi "callable" (es. Signal(...) invece di Signal.new(...)).

local Counter = {}
Counter.__index = Counter

Counter.__call = function(self)
	self.Value += 1
	return self.Value
end

local counter = setmetatable({ Value = 0 }, Counter)

print(counter()) --> 1
print(counter()) --> 2

10__len e __concat

__len — operatore #
local Inventory = setmetatable({ Slots = { "Spada", "Scudo" } }, {
	__len = function(self)
		return #self.Slots
	end,
})

print(#Inventory) --> 2
__concat — operatore ..
local Nome = setmetatable({ Valore = "Mario" }, {
	__concat = function(a, b)
		local sa = typeof(a) == "table" and a.Valore or a
		local sb = typeof(b) == "table" and b.Valore or b
		return sa .. sb
	end,
})

print(Nome .. " Rossi") --> "Mario Rossi"

11Tabelle di sola lettura

Combinando __newindex (blocca le scritture) e __metatable (blocca l'accesso alla metatable stessa) si ottiene una tabella immutabile — ottimo per configurazioni condivise che nessun modulo dovrebbe poter modificare per errore.

local function ReadOnly(t: {[any]: any})
	return setmetatable({}, {
		__index = t,
		__newindex = function(_, key, _)
			error("Tentativo di modificare una tabella read-only: " .. tostring(key), 2)
		end,
		__metatable = "Locked", -- getmetatable() restituirà questa stringa, non la vera metatable
	})
end

local Config = ReadOnly({
	MaxPlayers = 10,
	GameName = "Il Mio Gioco",
})

print(Config.MaxPlayers) --> 10, la lettura funziona normalmente
Config.MaxPlayers = 20 -- ERRORE: "Tentativo di modificare una tabella read-only: MaxPlayers"
__metatable impedisce anche che qualcuno chiami setmetatable(Config, altraCosa) per "scassinare" la protezione — se è impostato, setmetatable lancia un errore su quella tabella.

12Bypassare le metatable: raw*

A volte hai bisogno di leggere/scrivere/confrontare una tabella ignorando completamente i suoi metamethods — ad esempio dentro l'implementazione dei metamethods stessi, per evitare loop infiniti.

FunzioneEquivalente aMa...
rawget(t, k)t[k]...ignora __index
rawset(t, k, v)t[k] = v...ignora __newindex
rawequal(a, b)a == b...ignora __eq
rawlen(t)#t...ignora __len

13Quando usarle davvero (in Roblox)

✅ Usale quando...
  • Stai creando un modulo/classe riutilizzabile (Signal, Maid, Promise, Spring, Trove...).
  • Vuoi ereditarietà tra "classi" custom.
  • Vuoi operatori matematici naturali su un tuo tipo (es. una classe Vettore custom).
  • Vuoi proteggere una config condivisa da scritture accidentali.
  • Vuoi valori di default automatici senza riempire ogni tabella a mano.
  • Vuoi loggare/validare ogni scrittura su una tabella (debug, dev tools).
🚫 NON servono quando...
  • Ti basta una tabella semplice con pochi campi — aggiungono complessità inutile.
  • Il tuo "oggetto" viene creato/distrutto migliaia di volte al frame — hanno un piccolo overhead di performance.
  • Puoi risolvere lo stesso problema con una funzione pura che riceve dati e restituisce dati.
  • Stai solo raggruppando dati (DTO/config) senza bisogno di metodi o comportamento custom.
Regola pratica: se ti stai chiedendo "questa cosa ha bisogno di comportamento (metodi, ereditarietà, operatori) oltre che di semplici dati?" — se la risposta è sì, le metatable sono lo strumento giusto. Se ti serve solo un contenitore di valori, una tabella normale va benissimo.

1Cos'è Vide e perché usarlo

Vide è una libreria Luau reattiva per creare interfacce utente in Roblox, creata da centau e ispirata a SolidJS. A differenza di framework basati su Virtual DOM (come Roact/React-Lua), Vide lavora direttamente con le istanze reali di Roblox e usa un sistema di reattività a grana fine basato su sources ed effects.

Le scelte di design principali di Vide:
  • Sintassi minimale — poco boilerplate per creare UI.
  • Data oriented — il flusso dei dati guida l'interfaccia, non il contrario.
  • Compatibile col typechecking di Luau.
  • Indipendente dalle istanze — la logica reattiva non dipende dagli oggetti Roblox specifici.

Il concetto più importante da imparare, e che vedremo passo passo, è quello di scope (ambito): la reattività di Vide si basa su scope stabili e reattivi che si annidano tra loro, permettendo a Vide di gestire automaticamente la pulizia della memoria (garbage collection) senza dover disconnettere manualmente eventi ovunque.

Installazione minima (esempio concettuale)

local vide = require(ReplicatedStorage.Packages.vide)

local create = vide.create
local source = vide.source
local effect = vide.effect
local root = vide.root

2Creare elementi con create()

Le istanze si creano con create(). Le parentesi () possono essere omesse quando si chiama la funzione con una stringa o una tabella letterale, per brevità.

local create = vide.create

return create "ScreenGui" {
    create "Frame" {
        AnchorPoint = Vector2.new(0.5, 0.5),
        Position = UDim2.fromScale(0.5, 0.5),
        Size = UDim2.fromScale(0.4, 0.7),

        create "TextLabel" {
            Text = "hi"
        },

        create "TextLabel" {
            Text = "bye"
        },

        create "TextButton" {
            Text = "click me",

            Activated = function()
                print "clicked!"
            end
        }
    }
}
Regola d'oro della sintassi:
  • Chiave stringa → imposta una proprietà (es. Text = "hi").
  • Chiave numerica (implicita, come negli array) → aggiunge un figlio (un'altra istanza creata con create).
  • Assegnare una funzione a una chiave che corrisponde a un evento (es. Activated) lo connette automaticamente.

3Componenti

Vide incoraggia a separare le diverse parti della UI in funzioni chiamate componenti. Un componente è semplicemente una funzione che crea e restituisce un pezzo di UI, riutilizzabile ovunque.

Button.luau
local create = vide.create

local function Button(props: {
    Position: UDim2,
    Text: string,
    Activated: () -> ()
})
    return create "TextButton" {
        BackgroundColor3 = Color3.fromRGB(50, 50, 50),
        TextColor3 = Color3.fromRGB(255, 255, 255),
        Size = UDim2.fromOffset(200, 150),

        Position = props.Position,
        Text = props.Text,
        Activated = props.Activated,

        create "UICorner" {}
    }
end

return Button
Menu.luau
local create = vide.create
local Button = require(Button)

local function Menu()
    return create "ScreenGui" {
        Button {
            Position = UDim2.fromOffset(200, 200),
            Text = "back",
            Activated = function()
                print "pagina precedente"
            end
        },

        Button {
            Position = UDim2.fromOffset(400, 200),
            Text = "next",
            Activated = function()
                print "pagina successiva"
            end
        }
    }
end

Un singolo parametro props (una tabella) viene usato per passare le proprietà al componente — esattamente come nel modello a props di React.

4Sources — lo stato reattivo

Le sources sono oggetti speciali che memorizzano un singolo valore e rappresentano il cuore della reattività di Vide.

source(value)

Crea una nuova source. Il valore passato è il valore iniziale.

local source = vide.source

local count = source(0)

count(count() + 1) -- imposta: incrementa count di 1
print(count()) -- legge: stampa il valore attuale

La stessa funzione restituita da source() serve sia per leggere (chiamata senza argomenti) sia per scrivere (chiamata con un argomento) il valore.

Derivare una source con una funzione semplice

Le sources possono essere "derivate" avvolgendole in una funzione:

local count = source(0)

local text = function()
    return "count: " .. tostring(count())
end

print(text()) -- "count: 0"
count(1)
print(text()) -- "count: 1"

Questo di per sé si potrebbe fare anche con variabili semplici — l'utilità reale delle sources emerge con gli effects, visti nella prossima sezione.

5Effects — reagire ai cambiamenti

Gli effects sono funzioni eseguite in risposta agli aggiornamenti di una source. Una source e un effect sono l'equivalente di un segnale e una connessione.

effect(fn) Reactive Scope 
local count = source(0)

effect(function()
    print("count: " .. count())
end)

-- stampa subito "count: 0"
count(1)
-- stampa "count: 1"

Qualunque source letta dentro un effect viene tracciata automaticamente e farà rieseguire l'effect quando quella source cambia. L'effect esegue subito la sua callback una prima volta per capire quali sources sta leggendo.

Il tracciamento funziona anche annidato

local count = source(1)

local doubled = function()
    return count() * 2
end

effect(function()
    print("doubled count: " .. doubled())
end)
-- "doubled count: 2"
count(2)
-- "doubled count: 4"

Non conta quanto profondamente annidata sia una source dentro una funzione: viene tracciata comunque.

Ottimizzazione automatica: se una source viene impostata con lo stesso valore che aveva già, Vide non rieseguirà gli effect che dipendono da essa.

Leggere senza tracciare: untrack()

local untrack = vide.untrack

local a = source(0)
local b = source(0)

effect(function()
    print(`a: {a()} b: {untrack(b)}`)
end)

a(1) -- stampa "a: 1 b: 0"
b(1) -- non stampa nulla, "b" non è tracciata
a(2) -- stampa "a: 2 b: 1"

6Scope: Stabili vs Reattivi

Così come una connessione a un segnale può dover essere disconnessa, anche l'effect di una source potrebbe aver bisogno di essere "staccato". Disconnettere manualmente tanti segnali è però noioso e prolisso. Vide risolve il problema con il concetto di scope.

Scope Stabile Stable

Non viene mai rieseguito. Creato ad esempio da root().

Scope Reattivo Reactive

Può essere rieseguito. Creato ad esempio da effect().

Regole fondamentali:
  • Uno scope deve essere creato dentro un altro scope.
  • Uno scope reattivo non può essere creato dentro un altro scope reattivo — solo dentro uno stabile.
  • L'eccezione alla prima regola è root(), che crea lo scope iniziale, distrutto manualmente tramite la funzione "destructor" che restituisce.
  • Quando uno scope viene distrutto, tutti gli scope creati al suo interno vengono distrutti a cascata.
local root = vide.root

local count = source(0)

local function setup()
    effect(function()
        print(count())
    end)
end

setup() -- ERRORE: effect() ha provato a creare uno scope reattivo senza uno scope stabile

local destroy = root(setup) -- OK, perché effect() è chiamato dentro lo scope stabile di root()

count(1) -- stampa "1"
count(2) -- stampa "2"

destroy()

count(3) -- lo scope reattivo dell'effect è distrutto, non viene rieseguito
In pratica, non devi preoccuparti manualmente di creare ogni effect dentro uno scope stabile: crei tutta la tua UI e i tuoi effect dentro un'unica chiamata a root() a livello più alto, che mette insieme tutto. Da lì in poi qualsiasi effect creato sarà automaticamente al sicuro sotto quello scope.

Distruggere lo scope stabile di root() distrugge anche tutti gli scope reattivi creati al suo interno — importante perché un effect che aggiorna una proprietà di un'istanza UI mantiene un riferimento a quell'istanza in memoria; distruggendo l'effect, quel riferimento sparisce e l'istanza può essere raccolta dal garbage collector.

7Componenti Reattivi

I componenti reattivi in Vide si costruiscono combinando sources (per memorizzare i dati) ed effects (per mostrarli).

local function Counter()
    local count = source(0)

    local instance = create "TextButton" {
        Activated = function()
            count(count() + 1)
        end
    }

    effect(function()
        instance.Text = "count: " .. count()
    end)

    return instance
end

Ogni istanza di Counter() mantiene il proprio conteggio indipendente, perché la source count viene creata all'interno del componente stesso.

Sources esterne passate come props

local function CountDisplay(props: { count: () -> number })
    local count = props.count

    local instance = create "TextLabel" {}

    effect(function()
        instance.Text = "count: " .. count()
    end)

    return instance
end

local count = source(0)

CountDisplay { count = count }

count(1) -- CountDisplay si aggiornerà automaticamente

Le sources possono essere create internamente o passate dall'esterno — non ci sono restrizioni, purché l'effect che le usa venga creato dentro uno scope stabile.

8Effetti Impliciti e Children

Creare esplicitamente un effect solo per aggiornare una proprietà è ripetitivo. Puoi invece creare un effect implicitamente.

✅ Effetto implicito (consigliato)
local function Counter()
    local count = source(0)

    return create "TextButton" {
        Activated = function()
            count(count() + 1)
        end,

        Text = function()
            return "count: " .. count()
        end
    }
end
Effetto esplicito (equivalente)
local function Counter()
    local count = source(0)

    local instance = create "TextButton" {
        Activated = function()
            count(count() + 1)
        end
    }

    effect(function()
        instance.Text = "count: " .. count()
    end)

    return instance
end

Assegnare a una proprietà (non-evento) una funzione invece di un valore diretto crea implicitamente un effect che la mantiene aggiornata.

Figli reattivi

Anche i figli possono essere impostati in modo reattivo. Una source passata come figlio (con chiave numerica) può restituire un'istanza o un array di istanze. Vide crea automaticamente un effect che rimuove le istanze tolte e aggiunge quelle nuove a ogni aggiornamento della source.

local items = source {
    create "TextLabel" { Text = "A" }
}

local function List(props: { children: () -> { Instance } })
    return create "Frame" {
        create "UIListLayout" {},
        props.children
    }
end

local list = List { children = items } -- crea una lista con la TextLabel "A"

items {
    create "TextLabel" { Text = "B" },
    create "TextLabel" { Text = "C" }
}
-- questo de-parenterà automaticamente "A" e parenterà "B" e "C"

9Sources Derivate con derive()

Abbiamo già visto il modo base per derivare una source con una funzione semplice. Il problema è che se più effect usano la stessa funzione derivata, questa viene ricalcolata inutilmente per ognuno di essi.

local count = source(0)

local text = function()
    print "ran"
    return "count: " .. tostring(count())
end

effect(function() text() end)
effect(function() text() end)

count(1) -- stampa "ran" DUE volte, uno spreco
derive(fn) Reactive Scope

Esegue una funzione in uno scope reattivo per calcolare il valore di una nuova source, solo quando le sources lette al suo interno cambiano. Leggere la source derivata più volte restituisce un risultato cacheato.

local derive = vide.derive

local text = derive(function()
    print "ran"
    return "count: " .. tostring(count())
end)

effect(function() text() end)
effect(function() text() end)

count(1) -- stampa "ran" UNA sola volta

Poiché derive() crea uno scope reattivo, va chiamato dentro uno scope stabile, esattamente come effect(). Se il valore ricalcolato è uguale a quello vecchio, la source derivata non rieseguirà gli effect che la usano.

Derivare una source in questo modo è concettualmente simile a creare un effect che aggiorna un'altra source — ma va evitato farlo con un effect esplicito: un uso scorretto potrebbe creare accidentalmente loop infiniti nel grafo reattivo. Preferisci sempre derive() quando una source deve aggiornarsi in base a un'altra.

10Cleanup

A volte serve eseguire del codice di pulizia quando un componente viene distrutto, o dopo un effetto collaterale causato dall'aggiornamento di una source. Vide fornisce cleanup(), che mette in coda una callback da eseguire la prossima volta che uno scope reattivo viene rieseguito/distrutto, o quando uno scope stabile viene distrutto.

local cleanup = vide.cleanup

local count = source(0)

local destroy = root(function()
    effect(function()
        local x = count()
        cleanup(function() print(x) end)
    end)

    cleanup(function() print "root distrutto" end)
end)

count(1) -- stampa "0" (cleanup della run precedente, x=0)
count(2) -- stampa "1"
destroy() -- stampa "2" e "root distrutto"
Nota importante: le istanze Roblox non hanno bisogno di essere esplicitamente distrutte per liberare memoria — basta che vengano parentate a nil. Quindi non serve usare cleanup() solo per distruggere istanze. Attenzione però a connettere una funzione che referenzia un'istanza a un evento della stessa istanza: questo crea un riferimento circolare che impedisce la garbage collection. In quel caso usa cleanup() per disconnettere la connessione o distruggere esplicitamente l'istanza.

11Scope Dinamici: show, switch, indexes, values

Prima o poi serve creare e distruggere elementi UI dinamicamente in risposta agli aggiornamenti di una source. Vide fornisce le funzioni di scope dinamico: creano e distruggono scope per te, e restituiscono una source contenente il componente creato — puoi parentare direttamente questa source come figlio.

show(source, component, fallback?) Reactive Scope

Mostra un componente se la source è "truthy" (non falso/nil). Se fornito, mostra un componente di fallback quando è falsa.

local show = vide.show

function App()
    local toggled = source(false)

    return create "ScreenGui" {
        Button {
            Text = "Apri Menu",
            Activated = function()
                toggled(not toggled())
            end
        },

        show(toggled, Menu)
    }
end

root(function()
    App().Parent = game.StarterGui
end)
switch(source)(map) Reactive Scope

Mostra uno tra più componenti in base al valore di una source, usando una tabella di mappatura valore → componente.

local switch = vide.switch

local logged = source(false)

local button = switch(logged) {
    [true] = function()
        return Button { Text = "Esci", Toggle = logged }
    end,

    [false] = function()
        return Button { Text = "Accedi", Toggle = logged }
    end
}
indexes(source, constructor) Reactive Scope

Crea un componente per ogni indice di una tabella. Ogni componente vive nel proprio scope stabile indipendente. Vide controlla gli indici a ogni aggiornamento per evitare distruzioni/ricreazioni inutili degli elementi.

Il costruttore riceve: 1) una source contenente il valore all'indice, 2) l'indice stesso. Se il valore di un indice esistente cambia, il costruttore non viene rieseguito — viene solo aggiornata la source di quell'indice.

local indexes = vide.indexes

local function Todo(props: { Text: () -> string, Position: number, Activated: () -> () })
    return create "TextButton" {
        Text = function() return props.Position .. ": " .. props.Text() end,
        LayoutOrder = props.Position,
        Activated = props.Activated
    }
end

local function TodoList(props: { List: () -> { string } })
    return create "Frame" {
        create "UIListLayout" {},

        indexes(props.List, function(text, i)
            return Todo {
                Text = text,
                Position = i,
                Activated = function()
                    local list = props.List()
                    table.remove(list, i)
                    props.List(list) -- riassegna la tabella per far scattare l'update!
                end
            }
        end)
    }
end
Attenzione: se modifichi una tabella contenuta in una source, devi riassegnare la tabella alla source per far scattare l'aggiornamento: 
local src = source { 1, 2 }
local data = src()
table.insert(data, 3) -- nessun effect viene eseguito!
src(data) -- ORA gli effect vengono eseguiti
values(source, constructor) Reactive Scope

Stessa idea di indexes() ma applicata ai valori invece che agli indici. Il costruttore riceve: 1) il valore stesso, 2) una source contenente l'indice del valore.

Usa indexes() quando...Usa values() quando...
La source ha valori primitivi. Es: lista di statistiche di un personaggio/arma. Hai un set fisso di oggetti che possono essere riordinati. Es: lista giocatori, inventario, cronologia chat, notifiche.

Nella maggior parte dei casi entrambe producono lo stesso risultato visibile: la differenza principale è la performance (meno aggiornamenti/re-render nel caso giusto). values() è particolarmente utile per animare il riordino di elementi, dato che l'indice (come source) può essere usato per animare un cambio di posizione.

Ritardare la distruzione (animazioni in uscita)

Tutte le funzioni di scope dinamico supportano il ritardo della distruzione dello scope, utile per far girare un'animazione prima che l'istanza venga effettivamente rimossa. Basta restituire, dopo il componente, il numero di secondi di ritardo.

local function Menu(props: { Visible: () -> boolean })
    local transparency = spring(function()
        return if props.Visible() then 0 else 1
    end)

    return create "Frame" { BackgroundTransparency = transparency }
end

local toggled = source(true)

create "ScreenGui" {
    show(toggled, function(_, present)
        return Menu { Visible = present }, 3 -- 3 secondi di ritardo per completare l'animazione
    end)
}

toggled(false)
-- "present" diventa false immediatamente
-- la trasparenza inizia ad animarsi
-- dopo 3 secondi lo scope viene distrutto davvero

Se toggled torna a vero prima che il timer scada, il timer viene annullato e lo scope non viene distrutto.

12Actions

Le actions sono callback speciali che puoi passare insieme alle proprietà, per eseguire codice arbitrario su un'istanza appena creata.

action(fn) 
local action = vide.action

create "TextLabel" {
    Text = "test",

    action(function(instance)
        print(instance.Text)
    end)
}
-- stamperà "test"

Le actions possono essere incapsulate in funzioni riutilizzabili — ecco un esempio che ascolta i cambi di una proprietà esterna:

local function changed(property: string, callback: (any) -> ())
    return action(function(instance)
        local connection = instance:GetPropertyChangedSignal(property):Connect(function()
            callback(instance[property])
        end)

        -- ricorda di pulire la connessione quando lo scope viene distrutto,
        -- così l'istanza può essere raccolta dal garbage collector
        cleanup(connection)
    end)
end

local output = source ""

local instance = create "TextBox" {
    changed("Text", output)
}

effect(function()
    print(output())
end)

instance.Text = "foo" -- l'effect stamperà "foo"
La source output verrà aggiornata col nuovo valore della proprietà ogni volta che questa cambia esternamente (es. l'utente digita nella TextBox).

13Strict Mode

Durante lo sviluppo, dovresti usare lo strict mode di Vide, che aggiunge controlli di sicurezza extra e messaggi d'errore più chiari (soprattutto negli errori nei binding di proprietà).

vide.strict = true
Lo strict mode è abilitato automaticamente quando Vide viene richiesto con livello di ottimizzazione O0 o O1 (il default in Studio). Puoi impostare vide.strict = false se non lo desideri.

In strict mode, le sources derivate e gli effect vengono eseguiti due volte a ogni aggiornamento, per verificare che i calcoli delle derive siano puri e che ogni cleanup fatto dentro derive/effect funzioni correttamente:

vide.strict = true

local count = source(0)

local ran = 0
effect(function()
    count()
    ran += 1
end)

print(ran) -- 2
count(1)
print(ran) -- 4

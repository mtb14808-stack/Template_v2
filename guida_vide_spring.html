1Cos'è spring() e a cosa serve

vide.spring è una funzione di Vide che restituisce una nuova source il cui valore si muove costantemente verso il valore di una source di input, seguendo una simulazione fisica di una molla — invece di un'interpolazione lineare o a curva fissa (tween).

In pratica: invece di dire "vai da 0 a 100 in mezzo secondo con questa curva", dici "insegui questo valore target come se fossi attaccato a una molla". Il risultato è un movimento naturale che rallenta e accelera in modo fisicamente plausibile, e che può essere interrotto e ridiretto in ogni momento senza scatti innaturali (perché la molla conserva la sua velocità attuale).

È l'equivalente concettuale di TweenService ma basato su fisica anziché su curve di easing predefinite — simile a react-spring in ambito React o a Fusion.Spring.

2Firma della funzione e parametri

function spring<T>(
    source: () -> T & Animatable,
    period: number = 1,
    damping_ratio: number = 1
): (() -> T, SpringControl<T>)

type Animatable =
    number | CFrame | Color3 | UDim | UDim2 | Vector2 | Vector3 | Rect

type SpringControl<T> = ({
    position: T?,
    velocity: T?,
    impulse: T?
}) -> ()
ParametroTipoDefaultDescrizione
source funzione — Una source (o funzione derivata) che restituisce il valore target verso cui la molla deve muoversi. Deve essere di un tipo Animatable.
period number 1 Il tempo in secondi per un ciclo completo di oscillazione, se la molla fosse non smorzata. In pratica controlla la "velocità"/frequenza del movimento.
damping_ratio number 1 Quanta resistenza (smorzamento) viene applicata alla molla. Controlla quanto "rimbalza" prima di fermarsi. Vedi la sezione dedicata più sotto.

Il tipo Animatable include tutti i tipi Roblox più comuni per l'animazione UI: number, CFrame, Color3, UDim, UDim2, Vector2, Vector3, Rect.

3Cosa restituisce: valore + controllo

spring() crea uno scope reattivo interno per rilevare gli aggiornamenti della source di input, e restituisce una tupla di due elementi:

#TipoCosa fa
1. () -> T Una source di sola lettura contenente il valore attualmente animato della molla (quello da usare per aggiornare la proprietà UI, es. Position o BackgroundTransparency).
2. SpringControl<T> Una funzione di controllo per manipolare manualmente lo stato interno della molla: position, velocity, impulse.

La simulazione fisica gira internamente a 120 Hz agganciata all'evento Heartbeat di default, ma può essere controllata manualmente con vide.step(dt) se preferisci gestire tu il ciclo di aggiornamento.

4Capire il damping_ratio

Il damping_ratio è il parametro più importante per il "feeling" dell'animazione. Controlla se e quanto la molla oscilla prima di fermarsi sul valore target:

damping_ratio < 1
Underdamped

La molla oscilla superando il target prima di stabilizzarsi — effetto "rimbalzino" tipico delle UI moderne (es. un pop-up che apre con un piccolo overshoot).

damping_ratio = 1
Critically Damped (default)

La molla raggiunge il target nel modo più rapido possibile senza oscillare. È il comportamento di default, morbido e diretto.

damping_ratio > 1
Overdamped

La molla è più lenta nel raggiungere il target, senza mai superarlo — movimento pesante, "smorzato".

damping_ratio = 0
Undamped

Nessuno smorzamento: la molla oscilla all'infinito senza mai fermarsi (raramente utile in UI).

Regola pratica: usa un damping_ratio leggermente sotto 1 (es. 0.6–0.8) per un effetto "bouncy" gradevole in menu e pop-up; usa 1 per transizioni pulite e professionali (es. barre di progresso, fade).

5Esempio pratico completo

Un pannello che appare/scompare con un'animazione di trasparenza e posizione governate da una molla:

local create = vide.create
local source = vide.source
local spring = vide.spring

local function Panel(props: { Visible: () -> boolean })
    -- la molla insegue 0 o 1 in base alla visibilità richiesta
    local transparency = spring(function()
        return if props.Visible() then 0 else 1
    end, 0.4, 0.7) -- period=0.4s, damping_ratio=0.7 (leggero rimbalzo)

    return create "Frame" {
        BackgroundTransparency = transparency, -- effetto implicito: si aggiorna da sola
        Size = UDim2.fromOffset(300, 200)
    }
end

local visible = source(true)

Panel { Visible = visible }

visible(false) -- il pannello svanirà dolcemente invece di sparire di scatto

Nota che spring() restituisce direttamente una source (funzione get), quindi può essere assegnata a una proprietà esattamente come una qualunque altra source reattiva — Vide creerà automaticamente l'effetto implicito che tiene la proprietà aggiornata a ogni tick della simulazione.

Animare una posizione (Vector2/UDim2)

local targetPos = source(UDim2.fromScale(0.5, 0.5))

local animatedPos = spring(targetPos, 0.5, 1) -- damping=1, nessun overshoot

create "Frame" {
    Position = animatedPos
}

-- muovendo il target, il Frame si sposterà fluidamente seguendo la fisica della molla
targetPos(UDim2.fromScale(0.8, 0.2))

6Controllare la molla manualmente

Il secondo valore restituito da spring() è una funzione di controllo (SpringControl<T>) che permette di intervenire direttamente sullo stato fisico della simulazione, utile per casi come un drag interattivo o un "colpo" iniziale.

CampoEffetto
positionTeletrasporta istantaneamente la molla a un nuovo valore, senza animazione (utile per resettare lo stato senza far vedere il movimento).
velocityImposta direttamente la velocità corrente della molla (utile per continuare un movimento, es. dopo un rilascio da drag).
impulseApplica una "spinta" istantanea aggiuntiva alla velocità attuale, senza cambiare la posizione — ottimo per un piccolo "colpetto" quando l'utente clicca un bottone.
local value, control = spring(function() return 0 end, 0.3, 0.5)

-- dai un piccolo "colpetto" alla molla quando il bottone viene premuto,
-- come un feedback tattile visivo
create "TextButton" {
    Size = function() return UDim2.fromOffset(200 + value(), 50) end,

    Activated = function()
        control({ impulse = 15 }) -- piccola spinta di velocità
    end
}

7Uso con show() per animazioni in uscita

Il caso d'uso più comune di spring() è combinato con show() (o gli altri scope dinamici) per animare l'uscita di un elemento prima che venga effettivamente distrutto — dato che show() supporta un ritardo di distruzione in secondi.

local function Menu(props: { Visible: () -> boolean })
    local transparency = spring(function()
        return if props.Visible() then 0 else 1
    end)

    return create "Frame" {
        BackgroundTransparency = transparency
    }
end

local toggled = source(true)

create "ScreenGui" {
    show(toggled, function(_, present)
        return Menu { Visible = present }, 3 -- 3 secondi di margine per completare l'animazione
    end)
}

toggled(false)
-- "present" diventa false subito: la molla inizia ad animare la trasparenza verso 1
-- dopo 3 secondi lo scope (e quindi il Frame) viene distrutto davvero
Se toggled torna vero prima che il ritardo scada, la distruzione viene annullata e la molla può tranquillamente invertire rotta verso il valore aperto, dato che conserva la sua velocità attuale — nessuno scatto visivo.

8Avvisi e limiti

Attenzione: periodi (period) o damping ratio molto grandi possono "rompere" la simulazione della molla (instabilità numerica). Mantieni valori ragionevoli — tipicamente period tra 0.1 e 2 secondi, e damping_ratio tra 0 e 2.

Ricorda inoltre che:

  • spring() crea uno scope reattivo, quindi va chiamato dentro uno scope stabile (come tutte le altre funzioni reattive di Vide, es. effect() o derive()).
  • Il tipo di dato deve essere uno tra quelli supportati in Animatable — non puoi animare stringhe, booleani o tabelle arbitrarie.
  • La simulazione continua a girare "in background" ogni frame finché lo scope non viene distrutto: se crei tante molle contemporaneamente su UI complesse, valuta l'impatto sulle prestazioni.
